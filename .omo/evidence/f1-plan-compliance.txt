  DISCREPANCIES
================================================================================

1. QA assertion b2 — localStorage.theme not null on fresh load
   Status:  DOCUMENTED, NOT A PLAN VIOLATION
   Detail:  On fresh page load (system preference = light, no prior localStorage),
            next-themes resolved the system preference to "light" and immediately
            persisted it to localStorage. The QA assertion expected null (no prior
            user interaction), but got "light".
   Why it's acceptable: next-themes with enableSystem + defaultTheme="system"
            auto-resolves the OS preference and writes the resolved value to
            localStorage on first render. This is documented next-themes behavior,
            not a bug. The plan's acceptance criteria require the toggle to work
            correctly, which it does — the important invariant (localStorage value
            matches visual state) holds.
   Plan impact: NONE. The plan never required localStorage to be null initially.

2. Lint failure required a discovered fix (lint-fix-theme-changer.txt)
   Status:  PLAN-PLUS EVENT (strictly beneficial, in-scope)
   Detail:  The initial lint run during QA found two pre-existing issues in
            ThemeToggle.tsx: react-hooks/set-state-in-effect (useState+useEffect
            pattern) and @typescript-eslint/no-unused-vars (`theme` destructured
            but unused). A lint-fix task was executed that:
            - Replaced useState+useEffect with useSyncExternalStore (hydration guard)
            - Removed unused `theme` from destructuring, keeping only resolvedTheme+setTheme
            Post-fix: lint exit 0, tsc exit 0, smoke test all PASS.
   Why it's acceptable: The plan's acceptance criteria for todos 1-3 all require
            "npm run lint exits 0". The lint failure was pre-existing in the
            component, not introduced by the fix. The fix was necessary to meet
            the plan's own acceptance criteria. The result is strictly better than
            the plan required (cleaner code + lint pass).
   Plan impact: BENEFICIAL. No guardrails violated.

3. f2-code-quality-review.txt minor inaccuracy (cosmetic only)
   Status:  EVIDENCE TEXT STALE, CODE CORRECT
   Detail:  The f2 review (Check 1, line 19) lists "useEffect, useState" as
            imports in ThemeToggle.tsx, but the actual delivered file uses
            useSyncExternalStore (post lint-fix). This is a stale snapshot in
            the evidence text — the f2 review was likely written against the
            pre-lint-fix version. The actual code is correct and matches the plan.
   Plan impact: NONE. This is an evidence-documentation artifact, not a code issue.
